# 通用评测工作簿字段与配置

## 输入 CSV

CSV 至少包含：

`case_id,评测对象,场景分类,测试输入,难度,样本类型,预期表现,硬性约束,重点观察项,数据来源（AI合成）`

`case_id` 必须唯一；模型输出和评分结果不要写入 CSV，由工作台录入。

{
  "title": "产品输出质量评测汇总",
  "version": "eval-workbook-v1.0",
  "metrics": [

      "weight": 0.5,
      "definition": "输出是否达成目标卡中的核心结果",
      "method": "二值：达成=1；未达成=0",
      "anchors": "1=满足目标卡全部必要条件；0=任一必要条件缺失",

    },
    {
      "id": "M2",
      "name": "质量强度",

      "negative_examples": ["反例 1", "反例 2"],
      "disagreement": "用文辞偏好替代业务结果",
      "hard_line": "触发硬性错误时最高 2 分"
    }
  ],
  "veto": {
    "name": "硬性约束与事实一致性",
    "definition": "不得违反目标卡中的禁止项或安全/合规要求",
    "method": "二值：通过/不通过",
    "positive_examples": ["所有硬性约束均满足", "无安全/事实冲突"],
    "negative_examples": ["触发禁止项", "关键事实被改写"],
    "disagreement": "低影响措辞差异与硬性冲突混淆",

`kind` 只影响工作台数据验证和汇总归一化：`binary` 为 0/1，`scale5` 为 1–5，`number` 为自由数值。权重应合计 1；若不合计，工作簿应显示配置错误而不是静默归一化。

## 四个工作表

### 评测集

原样承载 CSV 的 10 个字段，冻结首行/首列并对长文本换行。

### 评分工作台

固定身份列后，按 config 动态添加指标列；再添加 `硬性否决（通过/不通过）`、`否决原因`、`评分理由`、`是否Bad Case（公式）`、上下文列和评分标准版本。模型输出、指标评分、裁定和理由初始为空。Bad Case 公式至少应覆盖：否决不通过、任一 binary 指标为 0、任一 scale5 指标≤2；未开始评分时保持空白。

### 评分标准

每个 metric 和 veto 一行，列为：`维度｜定义｜权重/门槛｜打分方式｜档位锚点｜正例｜反例｜易分歧点｜硬性线`。正例与反例各至少 2 个，档位必须可观察、可引用。

### 评分汇总

按指标动态列出已评分数和通过率/平均值；再列否决通过率、Bad Case 数、已填模型输出数和加权参考分。所有当前值引用工作台，不硬编码评分结果。否决通过率在没有裁定时为空并显示“待裁定”。

## 验收清单

- 恰好四个工作表：`评测集`、`评分工作台`、`评分标准`、`评分汇总`。
- `case_id` 唯一；默认 30 条或用户确认的数量。
- 难度、场景分类、样本类型比例按目标卡检查；每个核心指标至少 5 条覆盖。
- 所有指标均有定义、权重/门槛、评分方式、锚点、2 个正例、2 个反例、分歧点和硬线。
- 工作台输入列为空；动态数据验证和公式列覆盖所有 case。
- 汇总公式能随工作台录入更新，空白初始状态不显示虚假结果。
- 公式错误扫描无 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。
- 四个工作表均渲染检查，长文本、列宽、标题和状态可读。
